## 왜 Velite인가

Contentlayer는 개발이 멈췄고, next-mdx-remote는 아카이브됐습니다. Velite는 Zod 기반 스키마로 프론트매터를 검증하고, 빌드 결과에서 타입을 바로 뽑아줍니다.

## 스키마가 단일 진실 공급원

프론트매터 타입을 따로 선언하지 않습니다. 스키마 하나가 검증과 타입을 모두 맡습니다.

```ts title="velite.config.ts"
const posts = defineCollection({
  name: "Post",
  pattern: "posts/**/index.mdx",
  schema: s.object({
    title: s.string().max(99),
    date: s.isodate(),
    thumb: s.string().max(24),
    // 필수 필드가 빠지면 빌드가 실패함
    body: s.mdx(),
  }),
});
```

필드 하나가 빠지면 `velite build`가 실패하므로, 잘못된 글이 배포까지 가지 않습니다.

## 조회는 한 곳에서

페이지는 `#site/content`를 직접 읽지 않고 `lib/posts.ts`의 함수만 거칩니다. 초안 제외, 정렬, 번호 매기기 규칙이 한 파일에 모입니다.
